# 라우팅 경고 — 표를 쓰지 말고 볼트를 읽는다 (2026-09-03)

`vault new --dir … --type …` 에서 그 폴더에 처음 나타나는 type 이면 한 줄 경고한다.
거부가 아니다. 스키마 정본 「라우팅 — 2단계부터」의 2단계이고, vault-new 스킬은
이 경고가 있다고 이미 적어 두었는데 새 패키지에는 없었다.

## 손으로 쓴 표는 3주 만에 두 번 썩었다

옛 CLI(`reference/vault.py`)의 `ZONE_TYPES` · `SUBDIR_TYPES` 는 "볼트의 실제 분포로
뽑았다(08-11)"고 주석까지 달려 있었다. 그런데 얼려 둔 순간부터 볼트와 갈라졌다.

```
209 Principles  →  299 Principles      (08-31 정합화)
template        →  스키마에서 제거       (08-26)
```

표가 데이터에서 나왔다는 것과 표가 데이터를 따라간다는 것은 다른 말이다.
그래서 이번에는 표를 두지 않고 **호출 시점의 볼트를 그대로 표로 쓴다.**

## 왜 「처음」이 신호가 되나 — 재봤다

`.vault-graph.db` 로 2026-09-03 에 잰 값이다.

```
문서 4,179 중 자기 폴더의 다수 type 과 같은 것   3,764  (90.1%)
폴더 752 중 type 이 하나뿐인 폴더                  496
```

폴더가 type 을 90% 말해주니, 그 폴더에서 0번 나온 type 은 한 번 더 볼 가치가 있다.
반대로 임베딩 이웃은 type 을 못 말한다 — 08-26 이후 새 문서 5편의 vv 이웃 10개로
다수결을 내니 type 1/5, 대역 1/5 였다. 이웃은 「같은 종류」가 아니라 「출처」였다
(원칙의 이웃 9개가 전부 E-Project Learnings). type 은 폴더의 일이고 벡터의 일이 아니다.

## 규칙

- **가장 좁은 폴더가 말한다.** 정확한 `--dir` 에 typed 문서가 5개 이상이면 거기서 판정.
  모자라면 부모로 올라간다 — 대역까지. 어디서도 5개가 안 되면 침묵한다.
- **한 건이면 충분하다.** 그 폴더에 그 type 이 1번이라도 있으면 경고하지 않는다.
  `case` 가 200 에도 300 에도 가는 것처럼, 대응은 완전하지 않다.
- **그래프가 빼는 것은 이웃이 아니다.** `000 Index/Templates` · `900 Archive` 는 세지 않는다.
- **파일은 이미 쓰였다.** 경고는 `created:` 뒤에 stderr 로 나온다. 옛 표의 문구
  「보통 … 다. `t` 가 맞나」를 「… 는 여기서 처음이다 — 맞으면 그대로 둔다」로 바꿨다.
  질문은 대답을 요구하고, 선언은 판단을 남긴다.

## 비용

대역 하나의 frontmatter 를 읽는다. 실제 볼트에서 호출 한 번에 160~350ms 다 (2026-09-03).

```
400 Logic Forge/…/Vector-Search   175ms   폴더 2편 → 부모 「Layer 3. Database」 9편이 말했다
300 Runtime/301 Day Notes          190ms   log 349 — concept 에 경고
600 Content Observatory/601 Books  337ms   capture 723 · hub 94 — 가장 무거운 대역
```

`check_new` 가 이미 한 번 하는 스캔을 다시 하지만, 두 함수를 얽지 않는 값으로 냈다.

## 이어질 것

이 「처음」 건수가 쌓이면 그것이 곧 폴더·type 대응의 잔차다. 3부 T4 검토의
A(변형) — 어휘의 잔차 — 와 같은 모양이라, 경고가 잦은 자리가 곧 폴더를 나누거나
type 정의를 고칠 자리다.
